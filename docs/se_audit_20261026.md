Snapshot of maintainability, redundancy, and process health for `real2sim`
(~85 package modules, ~100 scripts, unit-only CI). This is a engineering-quality
audit, not a calibration or experiment-status report.

## Highest-risk redundancies

1. **Duplicate env/scene shells** (`sim/env.py` ↔ `panda/env.py`, scene assembly) — privileged metric schema can drift.
2. **Cartesian control fork** (`policy/adapters.py` ↔ `panda/adapter.py`) — clamp/IK/feedback paths must stay aligned.
3. **Evaluation harness clones** (`evaluation/run.py` ↔ `oracle.py` ↔ script-local loops).
4. **ACT vision backends** (`clip_act.py`, `dinov2_act.py`, `attention.py`) share the ResNet-swap bootstrap.
5. **`sim/camera_fit.py` (~1100 LOC)** mixes library, rendering, and CLI.
6. **Diagnostic script sprawl** — experiment drivers re-accumulate after cleanup passes.
7. **Inverted dependency** — visual waypoint imports grasp geometry from `evaluation.oracle`.

## Recommended engineering norms

1. Prefer `src/real2sim/` helpers over one-off `scripts/diag_*` logic.
2. Required config path keys must resolve in unit CI (path-ref test).
3. New diagnostics either get a pure-helper unit test or are archived with a restore manifest.
4. Embodiment changes that touch task geometry land once, shared.
5. Keep one evergreen status doc; dated notes are evidence, not the index.
