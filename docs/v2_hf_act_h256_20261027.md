## The actual saved contract

* Input: six observed joints, five arm values in degrees and gripper percent.
* Images: **top wrist camera first, iPhone second**, each RGB **640×360**.
* Actions: six absolute joint servo targets in the same degree/percent units.
* Prediction chunk: 50 actions; execution prefix: 10 actions.
* Model: ResNet18, hidden width 256, four encoder layers, VAE enabled.
* Saved native preprocessor/postprocessor state is used exactly once. The
  repository's 192×256 letterbox and normalization are not applied.

The source recording metadata establishes 25 Hz; the model's `experiment.json`
does not separately pin its clock. The diagnostic therefore uses 25 Hz, unchanged
500 Hz physics, and the saved 10-action execution prefix. This assumption is
explicit in the report. Policy-call means are approximately 118 ms for root and
124 ms for latest, including both rendered input images and native inference.
Simulation pauses while inference runs; those times do not establish real-time
camera-to-motor performance at a 40 ms control interval.

Only gripper actuator bounds are enforced by saturation before the static
command guard. Every raw arm target remains available for rejection; no arm
reference is silently clipped into validity. Neither tested checkpoint actually
required gripper saturation in these trials. No task goals or corrective IK
drive these learned commands.

Global camera registration is provisional. The `top` camera uses the pinned
SO-101 nominal CAD optical transform, not a measured physical wrist-camera
calibration. This preserves two distinct camera inputs instead of substituting
one camera image for the other, while leaving the optical mismatch visible.

## Training step and split provenance

`experiment.json` requests 40,000 updates/640,000 examples. However, the saved
`latest/training_state.pt`, inspected with `torch.load(weights_only=True)`, records
**step 30,000**, with saved best validation value 0.186338. The root weights are
different and do not carry an independently readable step tag. Therefore the
current repository revision does not establish that its published latest weights
completed 40,000 updates.

The new checkpoint uses 35 training episodes and six validation episodes, seed 42.
This differs from this project's historical 29/6/6 partition and includes some
formerly reserved episodes. Historical reserved-set claims must not be reused
for this newly trained checkpoint.

All six of its validation episodes start outside the current simulator's native
joint bounds: shoulder lift is about −104.4° to −104.8°, versus the native −100°
limit. Their first fully native-compatible frames occur 4.4–5.8 seconds into the
recording. The diagnostic retains the configured valid start rather than silently
clipping those original starts. This is another concrete reason to resolve
physical joint neutral/stop registration before interpreting replay mismatch as
a learning failure. The degree/percent unit convention itself matches the saved
normalizer and local source recording metadata.
